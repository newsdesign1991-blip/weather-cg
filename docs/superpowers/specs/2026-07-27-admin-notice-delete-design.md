# 관리자 공지 삭제 설계

## 목표

공지사항 목록에서 관리자가 잘못 등록한 공지를 즉시 숨길 수 있게 한다. 관리자 작성 공지뿐 아니라 프로그램에 기본 포함된 공지도 삭제 대상으로 삼으며, 삭제 결과는 현재 브라우저에서 새로고침 후에도 유지한다.

## 사용자 흐름

1. 공지사항 목록의 각 공지 오른쪽 위에 휴지통 버튼을 표시한다.
2. 관리자가 휴지통 버튼을 누르면 기존 공지 작성과 같은 비밀번호를 입력한다.
3. 비밀번호가 맞으면 해당 공지를 삭제할지 한 번 더 확인한다.
4. 확인하면 목록에서 즉시 사라지고 완료 안내를 표시한다.
5. 비밀번호가 틀리거나 어느 단계에서든 취소하면 저장 상태를 바꾸지 않는다.

## 저장 방식

- 관리자 작성 공지는 `wcg_notices` 배열에서 해당 ID를 제거한다.
- 기본 포함 공지는 별도의 삭제 ID 목록을 localStorage에 저장하고 `allNotices()`에서 제외한다.
- 삭제 ID 목록은 유효한 문자열 ID만 읽도록 방어적으로 처리한다.
- 삭제된 공지의 ID는 읽음 목록에서도 제거해 불필요한 상태를 정리한다.
- 서버가 없는 현재 구조를 유지하므로 삭제는 해당 PC·브라우저에만 적용된다. GitHub 배포 파일에 포함된 기본 공지 자체는 변경하지 않는다.

## UI

- 휴지통 버튼은 공지 카드 오른쪽 위에 배치하고 공지 본문과 겹치지 않게 여백을 확보한다.
- 버튼에는 `공지 삭제` 툴팁과 접근성 레이블을 제공한다.
- 위험 동작임을 알 수 있도록 빨간색 계열을 쓰며 호버·포커스 상태를 명확하게 표시한다.
- 삭제 후 공지 목록 모달을 다시 렌더링하여 결과를 즉시 보여준다. 마지막 공지를 삭제한 경우 빈 목록 안내를 표시한다.

## 오류 및 안전 처리

- 존재하지 않는 공지 ID를 삭제하려는 경우 저장 내용을 변경하지 않는다.
- 관리자 작성 공지와 기본 공지에 같은 ID가 있더라도 해당 ID 전체를 숨김 처리해 다시 나타나지 않게 한다.
- 비밀번호 검사는 기존 `NOTICE_PW` 값을 그대로 사용한다.
- 삭제 전 브라우저 확인 대화상자를 사용해 오조작을 방지한다.

## 테스트

- 삭제된 기본 공지가 전체 공지 목록에서 제외되는지 확인한다.
- 관리자 작성 공지가 저장 배열에서 제거되는지 확인한다.
- 삭제 ID가 새로고침 후에도 유지되는 저장 계약을 확인한다.
- 공지 카드마다 삭제 버튼과 공지 ID가 연결되는지 확인한다.
- 비밀번호 확인, 재확인, 삭제 후 목록 갱신 흐름을 확인한다.
- 기존 공지 작성·읽음 처리와 다른 VF 관련 회귀 테스트가 계속 통과하는지 확인한다.
