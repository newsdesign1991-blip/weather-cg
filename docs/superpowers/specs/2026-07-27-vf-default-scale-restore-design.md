# VF 배포 기본 스케일 복원 설계

## 목표

VF가 아닌 화면에서 작업용 VF 스케일이 `100%`로 선점되는 문제를 막고, 노말 VF를 처음 선택할 때 배포 기본 배치의 스케일을 정확히 적용한다.

## 원인

`syncPanelFromState()`가 모든 출력 화면에서 `vfScaleValue()`를 호출한다. 이 함수는 조회와 동시에 현재 값을 `S.vfScales`에 저장하므로 일반 화면을 여는 것만으로 `common` 또는 `warnsea` 그룹에 `100%`가 생긴다. 이후 `applyPreset()`은 이 작업용 값을 배포 프리셋의 `vfScale`보다 우선해 `86%/83%`가 무시된다.

## 변경

- VF가 아닌 화면에서는 `syncPanelFromState()`가 스케일을 읽기만 하고 `S.vfScales`를 만들지 않는다.
- VF 화면에서만 `vfScaleValue()`를 호출해 현재 그룹의 라이브 값을 사용한다.
- 해당 그룹에 라이브 값이 아직 없으면 `applyPreset()`이 배포 프리셋의 `vfScale`을 적용한다.
- 사용자가 VF에서 직접 조절한 라이브 값은 화면·지도 전환 중 계속 우선한다.
- `common`과 `warnsea`의 분리 규칙은 유지한다.

## 테스트

- 일반 화면 패널 동기화가 `vfScales.common`을 생성하지 않는지 검증한다.
- VF 첫 진입 시 라이브 값이 없으면 프리셋의 `86%`가 적용되는지 검증한다.
- VF에서 사용자가 조절한 라이브 값은 같은 그룹에서 유지되는지 검증한다.
- `warnsea` 그룹도 같은 규칙으로 독립 적용되는지 검증한다.
