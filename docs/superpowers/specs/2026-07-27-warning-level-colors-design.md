# 특보 단계별 독립 색상 설계

## 목표

특보 지도에서 같은 특보 종류라도 정확한 단계명이 다르면 각각 독립적으로 색상을 지정할 수 있게 한다. `폭염 경보`의 색을 바꿔도 `폭염 중대경보`가 바뀌지 않아야 하며, 이 규칙을 현재와 앞으로 들어오는 모든 특보 종류·단계에 동일하게 적용한다.

## 원인

현재 `wrnColors`는 특보 종류마다 `[주의보, 경보]` 두 색만 저장한다. `wrnColorOf()`와 들어온 특보의 색상 편집기가 단계명에 `경보`가 포함되면 모두 경보 색 배열을 사용하므로 `경보`, `중대경보`처럼 서로 다른 단계가 같은 저장 위치를 공유한다.

## 저장 구조

- 기존 `wrnColors`는 종류별 기본색 `[주의보 계열, 경보 계열]`로 유지한다.
- 새 `wrnLevelColors` 객체에 `특보종류|정확한단계명` 키로 사용자가 바꾼 색을 저장한다.
- 예: `폭염|경보`, `폭염|중대경보`, `호우|주의보`.
- `wrnColorOf(wrn, lvl)`는 정확한 단계별 색을 먼저 사용하고, 없을 때만 기존 `wrnColors` 기본색으로 폴백한다.
- 기존 프로젝트와 배포 기본값에 `wrnLevelColors`가 없어도 빈 객체로 시작해 이전 동작과 색을 유지한다.

## 편집 동작

- ‘들어온 특보’ 목록의 색상 입력은 해당 행의 `특보종류|정확한단계명` 한 항목만 변경한다.
- 같은 종류·같은 단계의 여러 지역은 계속 한 색을 공유한다.
- 같은 종류라도 단계명이 다르면 서로 영향을 주지 않는다.
- 사이드바의 기존 종류별 주의보·경보 기본색 편집은 새 단계가 처음 들어왔을 때 사용할 폴백 색을 정하는 기능으로 유지한다.
- 정확한 단계별 색을 이미 지정한 항목은 종류별 기본색을 바꿔도 덮어쓰지 않는다.

## 저장과 기본값

- 전체 프로젝트 저장은 기존처럼 상태 객체 전체를 저장하므로 `wrnLevelColors`도 함께 저장된다.
- 화면별 배치와 ‘모두의 기본값으로 굽기’에도 `wrnLevelColors`를 포함한다.
- 밝은/어두운 화면 간 위치 공유 로직이 색상 객체를 섞지 않도록 기존 색 보존 규칙을 유지한다.

## 우선순위

- 지도 구역에 여러 특보가 겹칠 때의 기존 우선순위는 바꾸지 않는다.
- 같은 종류 안에서는 이름에 `경보`가 들어간 단계가 주의보보다 우선하는 기존 규칙을 유지한다.
- 이번 변경은 색 저장의 독립성만 해결하며 특보 겹침 순서를 새로 정의하지 않는다.

## 오류 처리

- 새롭거나 알 수 없는 특보 종류는 기존처럼 회색 기본색을 생성한다.
- 비어 있거나 잘못된 `wrnLevelColors`가 저장돼 있으면 빈 객체로 정규화한다.
- 단계별 색 값이 없거나 유효하지 않으면 기존 종류별 기본색으로 폴백한다.

## 테스트

- `폭염|경보`와 `폭염|중대경보`가 서로 다른 색을 반환하는지 검증한다.
- 한 단계의 색을 변경해도 같은 종류의 다른 단계 색이 변하지 않는지 검증한다.
- 호우·대설 등 특보 이름에 관계없이 정확한 단계 키가 사용되는지 표 기반으로 검증한다.
- 단계별 색이 없을 때 기존 주의보·경보 기본색으로 폴백하는지 검증한다.
- `wrnLevelColors`가 화면별 프리셋 저장 키에 포함되는지 검증한다.
- 기존 공지 삭제 테스트와 VF 회귀 테스트가 계속 통과하는지 확인한다.
